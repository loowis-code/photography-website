# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal photography portfolio at pictures.loowis.co.uk. TanStack Start (React SSR, file-based routing) deployed on Cloudflare Workers, with Neon Postgres for data, Cloudflare R2 for images, and Auth.js (GitHub OAuth, single admin user) gating the admin area.

## Commands

```bash
npm run dev            # start dev server at localhost:3000
npm run build           # vite build + tsc --noEmit
npm run lint             # eslint src/
npm run format           # prettier --check
npm run format:fix       # prettier --write
npm test                 # vitest run (all unit tests, once)
npm run test:watch       # vitest watch mode
npm run test:e2e         # playwright, against a dev server it boots itself
npm run deploy            # build + wrangler deploy
```

Single test file: `npx vitest run src/lib/server/pagination.test.ts`
Single e2e file: `npx playwright test e2e/admin.spec.ts`

CI (`.github/workflows/ci.yml`) runs on every PR into `main`, in order: lint → format check → unit tests → `tsc --noEmit` → build → Playwright e2e. All must pass before merge. E2E tests run the dev server with `E2E_TEST_MODE=true`, which makes `requireAuth()` in the admin server functions short-circuit to a fake session (see `__E2E_TEST_MODE__`, defined in `vite.config.ts` and typed in `src/env.d.ts`) instead of hitting real GitHub OAuth.

## Workflow

- No direct pushes to `main` — all changes go through a PR, and CI must be green before merging.
- Husky + lint-staged run ESLint/Prettier on staged files at commit time.

## Architecture

**Data flow**: routes call server functions, never the database directly. `src/lib/server/*.ts` holds `createServerFn()` handlers — `images.ts`, `collections.ts`, `search.ts`, `reference.ts` are public reads; `admin-images.ts` and `admin-collections.ts` are the CRUD counterparts and all start with `await requireAuth()`. `src/lib/db.ts` (`getDb()`) opens a Neon connection per call using the tagged-template `sql` API, which parameterizes values automatically — build queries with the tag, not string concatenation. Dynamic `ORDER BY`/`WHERE` fragments (sort/filter) go through `sql.unsafe()` in `src/lib/server/pagination.ts`, which only ever receives values from a fixed internal map (`ORDER_BY_MAP`), never raw user input.

**Visibility semantics**: `images.visible` is meant to hide unpublished/draft photos from the public site. `getAllImages` and `getFeaturedImages` filter on `visible = true`; `getImageById`, `getImagesForMap`, and `searchImages` currently do not — a direct link, the map, or a search query can surface an image an admin has marked hidden. Confirmed as intentional (2026-07): direct links are meant to work even when an image isn't in the public galleries yet.

**Auth**: `src/lib/auth.ts` builds an Auth.js config with a single GitHub provider; the `signIn` callback only allows the account matching `ADMIN_EMAIL` — there is no multi-user concept anywhere in the app. Required env vars (`AUTH_SECRET`, `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET`, `ADMIN_EMAIL`) are validated eagerly and throw if missing.

**Images**: uploads go through `src/lib/r2.ts` as base64 data URLs in a JSON body (20MB cap), decoded to a `Buffer` and put into the `R2_BUCKET` binding under a UUID key; `R2_PUBLIC_URL` is prefixed to build the stored `url`. There is no resizing/variant pipeline — the uploaded original is what every page (thumbnail, modal, detail) renders directly.

**Routing**: file-based under `src/routes/`; `src/routeTree.gen.ts` is generated by the TanStack Router plugin — never hand-edit it. Admin routes live under `src/routes/admin/` behind `src/routes/admin/route.tsx`. Route `head()` functions build per-page meta/OG tags and JSON-LD (see `src/routes/images/$id.tsx` for the fullest example); `BASE_URL` (`src/lib/constants.ts`) is used to build absolute canonical/OG URLs.

**Pagination/sorting/filtering**: shared logic lives in `src/lib/server/pagination.ts` (`PAGE_SIZE`, `ORDER_BY_MAP`, `buildFilterClause`) and `src/lib/search-params.ts` (`validateImageSearch`, used as a route's `validateSearch`). Both `getAllImages` and `getCollectionWithImages` use these together, so changes to sort/filter options need updating in both places plus the shared `SortOrder`/`FilterType` types in `src/lib/types.ts`.

**UI components** (`src/components/`) pair each `.tsx` with a `.module.css` file (CSS Modules, no global class names outside `src/styles/globals.css`). `loowis-component-library` supplies shared chrome (e.g. `Header` in `Layout.tsx`) — check that package before building a new primitive that might already exist there.

**Cloudflare bindings**: declared in `wrangler.jsonc` (currently just `R2_BUCKET`). `worker-configuration.d.ts` is generated by `npm run cf-typegen` and gitignored — regenerate it after changing bindings rather than hand-editing.
